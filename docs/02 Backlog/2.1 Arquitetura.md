# Arquitetura — Site HG Smart

## Visão geral

Site estático de 31 páginas HTML servidas como estão, sem servidor de aplicação, banco de dados ou build no servidor. Todas as páginas usam o mesmo CSS (`assets/css/hg.css`) e o mesmo script (`assets/js/hg.js`), e as três coisas saem de um gerador em Python (`ferramentas/gerador-site/`), que é a fonte: a página, o CSS e o JS publicados são saída dele.

## Componentes

| Parte | Onde | Responsabilidade |
|---|---|---|
| Gerador | `ferramentas/gerador-site/` (`gen.py`, `dados.py`, `base.py`, `paginas.py`, `paginas2.py`, `sistema.py`, `hg.css`, `hg.js`) | Fonte das páginas, do CSS, do JS e do `design-system/`. Dados das lojas, formas de pagamento, marcas, FAQ, avaliações e campanhas em `dados.py`; cabeçalho, menu e rodapé em `base.py`. `<head>` (title, descrição, canonical, Open Graph, JSON-LD) é lido da página existente e preservado |
| Páginas institucionais | 20 arquivos `.html` na raiz | Home, quem somos, catálogo, acessórios, serviços, as 6 formas de pagamento, como comprar, FAQ, garantia, CEO, contato, políticas e a página 404 |
| Páginas das lojas | `lojas/index.html` e `lojas/<cidade>/index.html` (10 cidades) | Lista das unidades, mapa do RS com status "aberta agora" calculado no navegador, e uma página por loja, com SEO local |
| Estilo | `assets/css/hg.css` | Folha única nos tokens do `DESIGN.md` (gerada; fonte em `ferramentas/gerador-site/hg.css`) |
| Comportamento | `assets/js/hg.js` | Abertura (uma vez por sessão), cortina entre páginas, menu, status das lojas, filtros, carrossel de campanhas e movimento com GSAP + ScrollTrigger + Lenis; qualquer erro na camada de movimento devolve a página estática |

| Bibliotecas | `assets/vendor/` | GSAP, ScrollTrigger e Lenis, locais |
| Mídia | `assets/img/`, `assets/lojas/`, `assets/fontes/` | Imagens do site e das lojas, fontes |
| Mídia sem uso | `assets/hero/`, `assets/video/`, `assets/audio/`, `assets/css/site.css`, `hero-cinematic.css`, `assets/js/site.js`, `motion.js`, `banner.js`, `hero-cinematic.js` | Restos da versão anterior e da abertura cinematográfica; nenhuma página carrega |
| SEO | `robots.txt`, `sitemap.xml` e dados estruturados nas páginas | Indexação; o `robots.txt` libera buscadores de IA de propósito |

## Fluxo dos dados

Nenhum dado entra pelo site: não há formulário, login nem medição. O visitante navega pelas páginas e sai por link para WhatsApp, Google Maps ou redes sociais. Os dados das lojas (endereço, horário, contato) ficam escritos nas páginas e no dado estruturado.

## Banco de dados

O site novo não usa banco. Os WordPress do servidor (site antigo e blogs) usam banco de dados no próprio servidor, fora deste repositório; detalhes a confirmar na inspeção pelo WHM.

## Integrações

WhatsApp, Google Maps, Instagram, Facebook, TikTok e YouTube, por link; mapa e Instagram incorporados nas páginas de loja. Detalhes em `docs/01 Informações Projeto/1.1 Informações.md`.

- Hoje: servidor cPanel/WHM `br.vormir2984.com.br` com LiteSpeed. `https://hgsmart.com.br` roda o WordPress antigo e `/blog` roda o WordPress do blog, que fica.

Método de envio: a confirmar.

## Decisões tomadas

Registradas em `DESIGN.md`, na seção "O que este site não tem, por decisão":

- Sem build: HTML, CSS e JS servidos como estão.
- Sem requisição externa no que é do site: fontes e bibliotecas locais. A exceção são o mapa e o Instagram nas páginas de loja.
- Sem medição e, por isso, sem cookie próprio.
- Sem carrinho, checkout ou preço: o site é institucional.
- Buscadores de IA liberados no `robots.txt`, para a rede aparecer nas respostas deles.

## Riscos conhecidos

- O `sitemap.xml` e o `robots.txt` diziam ser gerados por `ferramentas/gerar-seo.js`, mas esse script não está no repositório; hoje os dois são atualizados à mão (o gerador do site não os toca).
- `assets/hero/`, `assets/video/` e `assets/audio/` somam 44 MB que nenhuma página usa; se `assets/` subir inteiro, vão junto.
- O `robots.txt` bloqueia `/assets/img/banners/original/`, pasta que não existe no projeto.
- Substituir a raiz inteira do servidor derruba o blog: `/blog` precisa ficar intocado.
- Os endereços do WordPress antigo saem do ar com a troca; sem redirecionamento 301, o Google perde as páginas indexadas.
- O servidor não envia HSTS, CSP, X-Frame-Options nem X-Content-Type-Options, e mostra a versão do PHP.
- Há dois blogs com o mesmo nome (`/blog` e `blog.hgsmart.com.br`), o que duplica conteúdo para o Google; o do subdomínio usa Elementor 3.11.5, muito atrás do 4.0.3 dos outros dois WordPress.
- Política de privacidade, termos de uso e política de cookies ainda são esqueleto (item 21 de `Site Planejamento/pendencias.md`).
